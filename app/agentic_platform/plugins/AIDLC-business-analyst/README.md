# AIDLC-business-analyst

Expert Business Analyst plugin that extracts business knowledge from documents to generate EPICs, business rules, personas, and BRDs following SAFe methodology.

## Description

This plugin analyzes source documents (requirements, specifications, interviews) and generates structured business artifacts. It transforms business narratives into actionable documentation for downstream consumers (Product Owner, Tech Architect, implementation teams).

## When to Use

Use this plugin when you need to:
- Generate BRDs automatically from document folders
- Extract EPICs and strategic initiatives from business requirements
- Document business rules with formulas, validation logic, and error handling
- Create user personas from stakeholder information
- Generate comprehensive Business Requirements Documents (BRDs)
- Define success metrics and KPIs
- Document compliance requirements

## How to Use

This plugin uses **skill-based auto-invocation** - simply describe what you need in natural language, and the appropriate skills will be automatically invoked.

### BRD Generation

**Two Generation Modes:**

The plugin supports both **Interview Mode** (section-by-section review) and **Direct Mode** (auto-generate all sections):

```
# Generate BRD - you'll be prompted to choose mode
Generate a BRD from the documents in ./business-docs
```

**Interview Mode (Recommended):**
- Review each section before proceeding to the next
- Request revisions or refinements for any section
- Gaps and conflicts identified and presented during generation
- Each section confirmed before moving forward

**Direct Mode:**
- Auto-generate all sections without stopping for review
- Faster but no section-by-section control
- Ideal for trusted sources or when template structure is well-known

**Workflow Steps:**
1. **Template Selection**: Plugin prompts for custom template document or offers predefined templates (Legacy Inscore, SAFE BRD)
2. **Document Normalization**: All formats converted to markdown (60-70% token reduction vs JSON mapping)
3. **Generation Mode Selection**: Choose between Interview Mode or Direct Mode
4. **Content Generation**: Sections generated by reading markdown directly with concise formatting (40-50% verbosity reduction)
5. **Ambiguity Detection**: Automatic detection of conflicts, gaps, vague language (mandatory)
6. **Traceability**: Optional Rally Epic hierarchy and source citations (template-conditional)
7. **Output**: Both BRD.md and BRD.docx created

**Supported Document Formats:**
- Markdown (*.md)
- PDF (*.pdf) - Text and table extraction
- Word Documents (*.docx) - Full content extraction
- Excel Spreadsheets (*.xlsx) - Tables, specific sheets, and cell ranges
- PowerPoint (*.pptx) - Slide content and structure
- Text Files (*.txt)
- Outlook Messages (*.msg) - Email content, headers, and attachments

**Examples:**
```
# Generate BRD with mode selection
Generate a BRD from the documents in ./business-docs

# With Rally Epic traceability
Generate BRD from ./docs --epic E12345
```

**Output:**
- `BRD.md` - Markdown format with template-driven sections (including Ambiguities analysis)
- `BRD.docx` - Word document format (converted automatically)

**Key Features:**
- **Dual Generation Modes** - Interview (section-by-section review) or Direct (auto-generate)
- **Template Selection Workflow** - Prompt for custom template before using predefined templates
- **Optimized document processing** (60-70% token reduction via markdown normalization)
- **Concise, actionable output** - Content Conciseness Principles reduce verbosity by 40-50%
- **Automatic ambiguity detection** - Identifies conflicts, gaps, vague language (mandatory)
- **Modular agent architecture** - Separate agents for document processing, ambiguity detection, traceability building
- Handles missing information gracefully with "[Not available in source documents]"
- Generates both .md and .docx formats
- Includes coverage summary showing data completeness
- Template-driven architecture adapts to custom or predefined templates

## Available Skills

### `ba-brd` - BRD Generation Skill

Direct BRD generation with dual-mode workflow (interview or direct), optimized token usage, and concise output formatting.

**Features:**
- Template selection workflow (custom → predefined fallback)
- Dual generation modes (interview vs direct)
- Optimized document processing (60-70% token reduction via markdown normalization)
- Content Conciseness Principles for 40-50% verbosity reduction
- Mandatory ambiguity detection
- Template-conditional traceability
- Complete end-to-end workflow

### `documents` - Document Conversion Skill

Converts between Markdown and various Office formats. Automatically used by BRD generation for document extraction and .docx output.

**Supported Formats:**
- **Word Documents** (DOCX ↔ Markdown) - Full formatting preservation
- **Excel Spreadsheets** (XLSX ↔ Markdown) - Tables, specific sheets/ranges
- **PDF Files** (PDF ↔ Markdown) - Text and table extraction
- **PowerPoint** (PPTX ↔ Markdown) - Slide content and structure
- **Outlook Messages** (MSG → Markdown) - Email content, headers, attachments
- **CSV Files** (CSV ↔ XLSX) - Spreadsheet conversion

**Key Features:**
- Auto-installs dependencies on first use
- Specific Excel range extraction (e.g., `--range Sheet1!A1:D10`)
- Multiple sheet handling
- Table detection in PDFs
- Attachment extraction from MSG files

### `brd-template` - BRD Structure Template

AI-powered template parser that converts ANY document into a reusable template using semantic analysis. Prompts user for custom template before falling back to predefined templates.

**Predefined Templates:**
- **SAFE BRD** (`pre-defined-templates/safe-brd-v1.1.md`) - Comprehensive SAFe methodology template with 15 sections
- **Legacy Inscore** (`pre-defined-templates/legacy-inscore-v1.0.md`) - Organization-specific legacy format for backward compatibility

**Template-Driven Architecture:** The BRD structure is dynamically extracted from templates, ensuring output matches your organization's format standards exactly.

**Template Version:** 2.1 (AI-powered semantic analysis)

### `ba-generate` - Artifact Generation Skill

Routes generation requests to specialized agents (EPIC, Business Rules, BRD). Use when creating new business documentation from source requirements.

### `ba-explore` - Exploration Skill

Explore and understand existing business requirements and artifacts including EPIC definitions, business rules, personas, and their relationships.

### `ba-validate` - Validation Skill

Routes validation requests to artifact validator or ambiguity detector based on intent. Use for quality assurance of business documentation.

### `rally-hierarchy` - Rally Integration Skill

Fetches and formats Rally portfolio hierarchy (Epic→Capability→Feature) for BRD traceability matrices. Wraps Rally API for hierarchy-specific queries.

### `gap-resolver` - Interactive Gap Resolution

Interactive skill to fill gaps in BRD content by prompting users for missing information and integrating responses into the document.

### `conflict-resolver` - Ambiguity Resolution

Interactive skill to identify and resolve conflicts or ambiguities in BRD content by presenting options to users and reconciling inconsistencies.

## BRD Structure (Template-Driven)

The generated BRD follows the structure defined in your custom template or selected predefined template:

**SAFE BRD Template Structure:**
- Title Page - Document metadata, project information, stakeholders
- Tracking Page - Version control, review, approval tables
- Table of Contents - Linked navigation
- Introduction - Document overview and context
- Purpose - Problem statement and objectives
- Scope - In-scope, out-of-scope, boundaries
- Assumptions - Project assumptions with IDs
- Business Requirements - Functional requirements with IDs
- Additional Context - Supporting information
- Rules - Business rules and validation logic with IDs
- Non-Functional Requirements - Performance, security, scalability
- Ambiguities and Clarifications - Detected gaps, conflicts, vague language (mandatory)
- Requirement Traceability Matrix - Links to Epic/Feature IDs (template-conditional)
- Source Documents Reference - Citation tracking (template-conditional)
- Appendix - Glossary, references, acronyms, change history

**Legacy Inscore Template Structure:**
- Document Version Control, Review, Approval
- Table of Contents
- Introduction, Purpose, Scope
- Assumptions, Business Requirements
- General Parameters (Screen mockup, field definitions, POM mapping)
- Rules, Non-Functional Requirements
- Appendix (Reference tables)

**Note:** The actual BRD structure will match your provided template exactly. Custom templates can have different section names, counts, and ordering.

## Content Conciseness Principles

The plugin applies aggressive conciseness strategies to reduce BRD verbosity by 40-50% while maintaining clarity:

**Core Strategies:**
1. **Prefer structured formats over prose** - Tables for requirements/rules/NFRs, bullet lists for objectives/scope
2. **Maximize information density** - Remove unnecessary articles, use action-oriented fragments, combine related items
3. **Use compact notation** - Mathematical symbols (∈, →, ∧, ∨), abbreviations, range notation
4. **Eliminate redundancy** - No examples/justifications, no duplicate information across sections
5. **Keep tables narrow** - Maximum 4 columns, combine related fields

**Section-Specific Guidelines:**
- **Requirements/Rules/NFRs** - Multi-column tables with abbreviated headers, compact notation
- **Objectives/Scope** - One-line bullet points, grouped items
- **Introduction/Summary** - Single paragraph or 3-5 bullets maximum
- **Ambiguities** - Compact table format only (ID | Section | Issue | Severity | Action)

## Ambiguity Detection

The plugin automatically detects and reports ambiguities, conflicts, and gaps in requirements during BRD generation via the dedicated **ambiguity-detector agent**. The Ambiguities section is mandatory in all generated BRDs.

### What is Detected

**1. Conflicting Statements**
- Data type conflicts: "User ID is string" vs "User ID is number"
- Opposing requirements: "must allow" vs "must prevent"
- Contradictory business rules: different maximum values, thresholds
- Boundary conflicts: inconsistent limits across documents

**2. Missing Definitions and Incomplete Rules**
- Undefined data fields mentioned without type/constraint definitions
- Incomplete if-then rules (condition without action or vice versa)
- Missing validation specifications
- Undefined actors/roles referenced but not defined

**3. Vague and Unclear Requirements**
- Subjective terms without metrics: "fast", "user-friendly", "secure"
- Approximate qualifiers: "approximately", "around", "roughly"
- Conditional terms: "should", "may", "might", "could"
- Undefined modifiers: "reasonable", "appropriate", "sufficient"

**4. Missing Acceptance Criteria**
- Functional requirements without testable acceptance criteria
- Non-testable or subjective acceptance criteria
- Incomplete process steps (missing actor, action, or outcome)

### Example Output

The Ambiguities section of the generated BRD includes:

```markdown
## Ambiguities and Clarifications

### Summary Statistics

| Severity | Count | Percentage |
|----------|-------|------------|
| High | 8 | 40% |
| Medium | 10 | 50% |
| Low | 2 | 10% |
| **Total** | **20** | **100%** |

### High Severity Ambiguities (P0 - Must Resolve Before Design)

| ID | Section | Issue | Recommendation |
|----|---------|-------|----------------|
| AMB-01 | Business Rules | Premium calculation formula lacks complete specification | Define explicit risk factor mappings |
| AMB-02 | Business Rules | Refund calculation logic undefined | Define eligibility, calculation method, timing |
```

### Benefits

- **Early Issue Detection:** Identify problems before design and implementation
- **Reduced Rework:** Clarify requirements upfront to avoid costly changes later
- **Quality Assurance:** Ensure requirements are clear, complete, and testable
- **Stakeholder Alignment:** Provide specific questions for stakeholder clarification
- **Risk Mitigation:** Surface conflicting assumptions early in the process

## Workflow

### BRD Generation Workflow
1. **Template Loading** - Load custom or predefined template structure
2. **Document Processing** - Convert all documents to normalized markdown format (DOCX/PDF/MSG → MD)
3. **Output Path Discovery** - 3-tier approach (metadata → patterns → user prompt)
4. **Generation Mode Selection** - Ask user: Interview Mode or Direct Mode
5. **Content Generation** - Read normalized docs directly, extract/condense content per section
6. **Ambiguity Detection** - Invoke ambiguity-detector agent (mandatory)
7. **Traceability Collection** - Invoke traceability-builder agent (template-conditional)
8. **Final Assembly** - Generate BRD.md and BRD.docx with complete sections

**Token Optimization:** Document-processor returns file paths instead of JSON content mappings, reducing token usage by 60-70%. BRD generator reads markdown files directly for maximum efficiency.

### Artifact Generation (with Confirmation)
1. **Request Analysis** - Determine what artifacts to generate
2. **Context ADLCing** - Read and analyze source documents
3. **Plan Presentation** - Present generation plan for user confirmation
4. **Generation** - Generate requested artifacts after confirmation
