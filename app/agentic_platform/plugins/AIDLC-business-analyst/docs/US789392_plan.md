# Implementation Plan: Ambiguity Detection for AIDLC-business-analyst

**User Story ID:** US789392

## Overview

Add ambiguity detection capabilities to the AIDLC-business-analyst plugin to automatically identify conflicting statements, undefined elements, vague requirements, and missing acceptance criteria across source documents during BRD generation.

**User Story:** As a Business Analyst, I want the agent to detect and report ambiguities in requirements, so that I can clarify gaps before finalizing the BRD.

## Approach

Create a new specialized `ambiguity-detector` agent that integrates into the existing BRD generation workflow between content extraction and document generation. The agent will leverage Claude's semantic understanding combined with pattern matching (via Grep) for detection, avoiding heavy NLP library dependencies.

## Architecture

### 1. New Agent: ambiguity-detector

**File:** `plugins/AIDLC-business-analyst/agents/ambiguity-detector.md`

**Purpose:** Read-only analyzer that detects five types of ambiguities:
1. Conflicting statements across documents (semantic conflicts)
2. Missing business rules and undefined data fields
3. Undefined actors/roles mentioned without clear definitions
4. Vague language and subjective terms without metrics
5. Functional requirements without acceptance criteria

**Integration Point:** Called by brd-generator in new Phase 1.5 (between content extraction and generation)

**Tools:** Read, Grep (read-only, no Write/Edit)

**Output:** Structured ambiguity report with severity scoring (High/Medium/Low)

## Detection Algorithms

### AC1: Conflict Detection
**Strategy:** Semantic comparison using Claude + pattern matching

**Process:**
1. Extract all statements about same entities across documents (fields, rules, requirements)
2. Use Claude semantic comparison to detect contradictions
3. Pattern match for: data type definitions, boundary conditions, must/shall statements
4. Score contradiction likelihood and severity
5. Generate side-by-side conflict reports with source references

**Patterns:**
- Field definitions: `(field|attribute|property) [A-Z][a-z]+ (is|must be)`
- Requirements: `(must|shall|will|should) (not )?(be |have)`
- Boundaries: `(maximum|minimum|max|min|limit|threshold)`

### AC2: Missing Business Rules & Undefined Elements
**Strategy:** Pattern-based detection + reference tracking

**Process:**
1. Identify business rule patterns (if-then, validation, decision logic)
2. Check for incomplete rules (if without then, validation without specification)
3. Build entity registries (actors, data fields)
4. Cross-reference mentions vs definitions
5. Flag undefined references with context

**Patterns:**
- Incomplete if-then: `if .{10,100}(?!then)`
- Field mentions: `the ([A-Z][a-z]+(?:\s[A-Z][a-z]+)*) field`
- Actor mentions: `(user|admin|customer|manager|operator)`

### AC3: Vague Language & Missing Tests
**Strategy:** Keyword detection + testability validation

**Process:**
1. Scan for vague qualifiers (subjective, approximate, conditional terms)
2. Check if quantified nearby (within 20 words)
3. Flag if no objective metric provided
4. Identify all functional requirements
5. Check for corresponding acceptance criteria
6. Validate testability (Given-When-Then or measurable)

**Patterns:**
- Vague qualifiers: `\b(should|may|might|approximately|around)\b`
- Subjective terms: `\b(user-friendly|intuitive|fast|secure|simple)\b`
- Functional requirements: `FR-\d+|(must|shall|will) (be able to|provide)`

### AC4 & AC5: Structured Reporting
**Output Format:**
- Section 14 in BRD with structured tables
- Each ambiguity includes: ID, Type, Entity, Severity, Description, Source References
- Context snippets (2-3 sentences before/after)
- Hyperlinks to relevant BRD sections
- Summary count by category and severity
- Clarity score (0-100)
- Recommended actions prioritized by severity

## Data Structures

```typescript
interface AmbiguityReport {
  summary: { total, byCategory, bySeverity, clarityScore }
  conflicts: Conflict[]
  gaps: BusinessRuleGap[]
  vagueRequirements: VagueRequirement[]
  missingAcceptanceCriteria: MissingAcceptanceCriteria[]
}

interface Conflict {
  id, type, entity, severity, statements[], recommendation
}

interface DocumentReference {
  fileName, documentPath, sectionName, pageNumber?, hyperlinkAnchor
}
```

**Severity Rules:**
- Conflicts: Data type (High), Business rule (High), Requirement (Medium)
- Gaps: Undefined field (High), Incomplete rule (High), Missing validation (Medium)
- Vague: Subjective without metric (High), Approximate value (Medium)
