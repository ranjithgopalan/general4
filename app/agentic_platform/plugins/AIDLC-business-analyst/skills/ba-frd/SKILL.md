Generate the Functional Requirements Document (FRD) for stage G2 of the Global
Workspace, from an approved PRD, the extracted business rules and the read-only
schema snapshot.

## When this runs

Stage G2 of `pipelines/uw-cr-global.yaml`. It consumes `prd` and
`business-rules`; it produces `frd`.

The Architect's SDD and SRD both consume the FRD, so an FRD that quietly invents
requirements propagates into the system design and then into generated code. That
is why the grounding rules below are not optional.

## Steps

1. **Read the inputs.** Approved `prd` and `business-rules` from the Global
   Workspace. Fetch the schema snapshot for real identifiers. Assemble KB context
   for legacy behaviour.
2. **Check before writing.** Report each input as found/missing/unapproved. If a
   required one is missing, stop and say so.
3. **Derive requirements** area by area. `FR-<area>-<nnn>`, one behaviour each,
   each with `source`, `rationale` and `verification`.
4. **Map the business rules.** Every rule in `business-rules` maps to at least
   one requirement, or appears in the gap list with a reason. An unmapped rule is
   a dropped requirement, which is the failure mode this stage exists to prevent.
5. **Write the traceability matrix**, both in Markdown and as
   `frd-traceability.json`.
6. **List the gaps and open questions** explicitly.

## Workspace Output Resolution (ALWAYS RUN FIRST)

Before writing any files, read `aidlc.config.json` and derive the output directory:

```
workspace_id → from aidlc.config.json
OUT_DIR      → workspaces/{workspace_id}/design/
```

Create `OUT_DIR` if it does not exist. Write ALL output files under `OUT_DIR`.

## Output files

| File | Purpose |
|------|---------|
| `workspaces/{workspace_id}/design/frd.md` | The document, for human review |
| `workspaces/{workspace_id}/design/frd-traceability.json` | `{"requirements": [{"id", "source", "rules", "verification"}]}` |
| `workspaces/{workspace_id}/design/frd-gaps.md` | Open questions, one per heading, each with why it matters |

## Deliverable filename requirement

Write the output to `workspaces/{workspace_id}/design/frd.md` (lowercase filename).
The pipeline deliverable check is case-sensitive on Linux — `FRD.md` will not be recognised.

## Grounding rules

1. **Cite or omit.** Every substantive statement traces to an approved upstream
   artefact or a KB citation. Write the citation inline as
   `[source: <artefact-type> v<version> / <section>]`.
2. **A refusal is not content.** The KB returns an explicit refusal when
   retrieval finds nothing. If you get one, say so in the document. Do not
   substitute plausible text -- that is precisely how a fabricated requirement
   enters the chain and survives to code.
3. **Missing input stops you.** If a declared input is absent or unapproved,
   stop and state what is missing. Do not infer it from the document title.
4. **Never invent identifiers.** Requirement IDs, table names, stored-procedure
   names and field names come from the inputs or the schema snapshot only.

## Generative AI Limitations (MANDATORY in every output)

Every document you produce MUST carry this block verbatim near the top:

> **This document was generated by a Large Language Model.** It may contain
> hallucinated requirements, may have lost detail through context compaction, and
> may be confidently wrong. It is a draft for human review, not an authority.
> No requirement in this document may be treated as approved until a named
> human approver has signed it off at the pipeline stage gate.

Never remove or soften it. It is required by PRD section 2 and is the reason the
artefact is publishable at all.

## Coverage self-check before you finish

- [ ] Every business rule is mapped or listed as a gap
- [ ] Every requirement has `source`, `rationale`, `verification`
- [ ] Every inference is labelled `source: INFERRED`
- [ ] Data requirements use only real schema identifiers
- [ ] The GenAI limitations block is present verbatim
- [ ] No requirement is described as approved
- [ ] Output file is named `frd.md` (lowercase)

## Reporting to the AIDLC Platform (ECS UI tracking)

> **SERVER CLI GUARD:** If `aidlc.config.json` does **not** exist in your current
> working directory, skip this entire ECS section and run only the main workflow
> above. These steps are for the **local Claude Code session only**.

Run Step 0 and Step 0.5 **before** starting the main workflow above so ECS
captures the full local execution time. Run Steps 1–3 after `frd.md` is written.
Requires `aidlc.config.json` in the project root and `$env:AIDLC_TOKEN` set.

Note: `PATCH /pipeline-runs/{id}/status` and `POST /pipeline-runs/{id}/deliverables`
are not supported by this server. The `execute: true` + worktree pre-population
pattern is the only supported completion path.

**Step 0 — Read config and resolve output directory**
```powershell
$cfg     = Get-Content "aidlc.config.json" | ConvertFrom-Json
$BASE    = $cfg.central_base_url
$TOKEN   = [System.Environment]::GetEnvironmentVariable($cfg.auth.bearer_env)
$WS      = $cfg.workspace_id
$HDR     = @{ Authorization = "Bearer $TOKEN"; "Content-Type" = "application/json" }
$OUT_DIR = "workspaces\$WS\design"
New-Item -ItemType Directory -Force $OUT_DIR | Out-Null
Write-Host "Output directory: $OUT_DIR"
```

**Step 0.5 — Create ECS run BEFORE local work begins (captures true start time)**
```powershell
# Cancel stale queued runs for frd stage (worktree=null means they never started)
$allRuns = (Invoke-RestMethod -Uri "$BASE/pipeline-runs?workspace_id=$WS" -Headers $HDR).runs
$allRuns | Where-Object { $_.stage_key -eq "frd" -and $_.state -eq "queued" -and (-not $_.worktree) } | ForEach-Object {
    Invoke-RestMethod -Uri "$BASE/pipeline-runs/$($_.run_id)/cancel" -Headers $HDR -Method Post | Out-Null
}
$body0   = @{ stage = "frd"; workspace_id = $WS; execute = $true; force = $true } | ConvertTo-Json
$init    = (Invoke-RestMethod -Uri "$BASE/pipeline-runs" -Headers $HDR -Method Post -Body $body0).run
$RUN_ID  = $init.run_id
$WT_PATH = $init.worktree
if ($WT_PATH) { New-Item -ItemType Directory -Force -Path $WT_PATH | Out-Null }
Write-Host "ECS run created: $RUN_ID  (queued_at = true start time)"
Write-Host "Worktree: $WT_PATH"
```

→ **Now execute the skill workflow above.** When `$OUT_DIR/frd.md` is written, continue below.

**Step 1 — Pre-populate worktree with deliverables (recover if CLI timed out)**
```powershell
# If initial run failed (CLI hit max_turns during generation), create a fresh run
$status = (Invoke-RestMethod -Uri "$BASE/pipeline-runs/$RUN_ID" -Headers $HDR).run
if ($status.state -in @("failed","cancelled")) {
    Write-Host "Run $RUN_ID ended as '$($status.state)'. Creating fresh run..."
    $bodyF   = @{ stage = "frd"; workspace_id = $WS; execute = $true; force = $true } | ConvertTo-Json
    $fresh   = (Invoke-RestMethod -Uri "$BASE/pipeline-runs" -Headers $HDR -Method Post -Body $bodyF).run
    $RUN_ID  = $fresh.run_id
    $WT_PATH = $fresh.worktree
    Write-Host "Fresh run: $RUN_ID"
}
if ($WT_PATH) {
    $destDir = "$WT_PATH\workspaces\$WS\design"
    New-Item -ItemType Directory -Force -Path $destDir | Out-Null
    Copy-Item "$OUT_DIR\frd.md"                  "$destDir\" -Force
    Copy-Item "$OUT_DIR\frd-traceability.json"   "$destDir\" -Force -ErrorAction SilentlyContinue
    Copy-Item "$OUT_DIR\frd-gaps.md"             "$destDir\" -Force -ErrorAction SilentlyContinue
    Write-Host "Deliverables pre-populated in worktree — server CLI will finalize promptly."
}
```

**Step 2 — Poll until `waiting_for_approval`**
```powershell
$maxWait = 600   # 10 minutes
$elapsed = 0
do {
    Start-Sleep -Seconds 15
    $elapsed += 15
    $check = (Invoke-RestMethod -Uri "$BASE/pipeline-runs/$RUN_ID" -Headers $HDR).run
    Write-Host "[$elapsed s] state = $($check.state)"
} while ($check.state -notin @("waiting_for_approval","completed","failed","cancelled") `
         -and $elapsed -lt $maxWait)

switch ($check.state) {
    "waiting_for_approval" {
        Write-Host "✓ FRD stage is waiting for Business Analyst approval."
        Write-Host "  ECS: https://poc-ecs-build-ui.npsdlchgapp.us-east-1.aws.aig.net/aidlc-platform-management/pipeline"
    }
    "failed" {
        Write-Host "✗ Run failed: $($check.error)"
        Write-Host "  Check the ECS dashboard and retry via /launch $WS"
    }
    default {
        Write-Host "Run ended with state=$($check.state)"
    }
}
```
