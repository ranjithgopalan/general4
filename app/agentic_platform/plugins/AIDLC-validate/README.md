# Requirements Validator Plugin

Requirements completeness validation plugin for SDLC artifacts across all stages.

## Overview

The requirements-validator plugin validates COMPLETENESS from ground truth documents to generated artifacts:

- **EPIC Coverage**: BRD → EPIC validation
- **Feature Coverage**: PRD/EPIC → Features validation
- **Story Coverage**: Features → User Stories validation
- **Code Traceability**: Stories → Code traceability analysis
- **Full Chain**: End-to-end validation from BRD to code

## Usage

### Skills-Based Invocation

The plugin provides requirements validation through skills that are automatically invoked based on your request:

**Requirements Completeness Validation:**
```
Validate requirements completeness
Check EPIC against BRD
Validate features against PRD
Check story coverage from features
Analyze code traceability from user stories
Perform full chain validation from BRD to code
```

**Available Skills:**
- `requirements` - Unified requirements completeness validation
- `rai` - Responsible AI validation (if applicable)
- `validation-strategies` - Content matching, confidence scoring, gap reporting

**Validation Types:**
- BRD → EPIC validation
- PRD → Features validation
- Features → Stories validation
- Stories → Code traceability
- Full chain end-to-end validation

### Coverage Reports

| Report | Purpose | Generated By |
|--------|---------|--------------|
| `COMPLETENESS-REPORT.md` | Unified validation report | requirements-validator-router |

## Workflow

### Standard Validation Flow

1. **User invokes** `/validate-requirements` with optional type
2. **Router analyzes** request and determines validation type
3. **Router asks** for ground truth document path (if not specified)
4. **Router presents** validation plan for approval
5. **User confirms** the plan
6. **Router delegates** to specialized validator(s)
7. **Validators compare** source against targets
8. **Validators report** gaps with evidence and confidence
9. **Router aggregates** results into unified report
10. **User receives** COMPLETENESS-REPORT.md for review

### Validation Type Detection

| Keywords in Request | Validation Type | Validator |
|---------------------|-----------------|-----------|
| BRD, business requirements, EPIC | BRD → EPIC | epic-coverage-validator |
| PRD, product requirements, features | PRD → Features | feature-coverage-validator |
| stories, user stories, backlog | Features → Stories | story-coverage-validator |
| code, implementation, traceability | Stories → Code | traceability-analyzer |
| full, complete, end-to-end, all | Full chain | All validators |

## Confidence Levels

| Level | Criteria | Human Action |
|-------|----------|--------------|
| **HIGH** | Explicit requirement, comprehensive search, no match | Brief verification |
| **MEDIUM** | Implicit requirement, partial match possible | Careful review |
| **LOW** | Ambiguous requirement, fuzzy match only | Thorough verification |

## Key Distinctions

| This Plugin | vs Other Plugins |
|-------------|------------------|
| `requirements-validator` | Checks COMPLETENESS (what's missing) |
| `artifact-validator` | Checks QUALITY (what's wrong) |
| `code-validator` | Checks CODE STANDARDS (patterns/style) |
| `documents-maintainer` | Creates documentation (writes docs) |
| `security-reviewer` | Checks SECURITY issues |

## Guardrails

- **Ground truth required**: Always validates against user-specified source documents
- **User approval**: Always presents plan before validation
- **Evidence-based**: Every gap cites source location and confidence
- **HITL mandatory**: All findings require human verification
- **Read-only**: Never modifies source documents or artifacts
- **Accuracy disclaimer**: Reports estimated accuracy (70-80%)

## Limitations

- **Semantic matching**: May miss paraphrased requirements
- **Large documents**: Partial processing for 50+ page documents
- **Code traceability**: Inherently less reliable (60-70% accuracy)
- **Format support**: Best with structured formats (YAML, MD)

## Version

- **Plugin Version**: 2.0.0
- **Multi-Agent Architecture**: Router + 4 specialized validators
- **Confidence Scoring**: HIGH/MEDIUM/LOW levels
- **HITL Required**: All validation findings
